CASE STUDY · ADMINISTRATIVE WORKFLOW

加班管理與
行政彙整系統

把加班申請、主管審核、角色權限與行政彙整整理成同一套可操作流程。目前這套系統由國立成功大學教務處教學發展中心實際使用，協助內部加班資料處理與管理。

實際使用單位：國立成功大學教務處教學發展中心。單位官方網站 ↗。Production 帳號、正式資料庫與使用者資料不公開；本作品頁不代表校方對公開 repository 的背書，正式加班認定仍以校方制度與程序為準。

01 / Workflow

不是單純表單，而是一條完整的行政流程。

同仁日期、時段、加班事由與時數
主管待審核清單、核准或駁回
秘書／管理者行政彙整、使用者與角色管理
D1申請、帳號、session、approval log

02 / Backend rules

Time validation後端重新驗證加班開始時間、30 分鐘區間與申請時數，避免只信任前端輸入。
Overlap control同一天已有未駁回申請時，檢查時段是否重疊，避免重複送出。
Role boundary同仁、主管、秘書與管理者有不同查詢與操作權限，敏感 API 再做 server-side 授權。
Session security首次登入改密碼、PBKDF2-SHA256 密碼雜湊、token hash 與 HttpOnly session cookie。

03 / Production boundary

實際使用與公開展示分開。

  • Production 環境由實際使用單位操作，不在 Portfolio 公開登入入口。
  • 公開 source 不包含正式人員姓名、Email、加班事由、密碼、token 或 D1 production identifier。
  • 作品集只說明本人開發的系統流程與技術，不將它描述成「成大官方加班系統」。
  • 正式加班申請、認定與核銷仍依校方正式系統與行政程序。

05 / Takeaway

重點是把日常行政問題做成真正有人使用的工具。

這個專案的價值不只在 React 或 Cloudflare，而是把原本分散的申請、審核、權限與彙整工作整理成一條可執行的流程，並實際投入成大教發中心內部使用。
